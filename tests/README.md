# 品質檢查

使用 Node.js 24 內建測試工具，無需額外測試套件：

```sh
npm run build:gas
npm test
```

## 自動測試範圍

涵蓋純關卡規則、詞庫、句型、大廳獎勵與複習、冒險續玩、口說取消／過期回呼、完整 GAS 單檔與舊 helper 並存、寫入前後故障、日誌中斷、跨模式合併、事件防重、兩分頁佇列、舊陣列遷移、儲存額度／拒絕、學生切換、教師工作階段與到期。

圖卡測試使用真實第一關出口邏輯，檢查門未開不可通關、隱藏父物件不可互動、延後出現物件可刷新、重試渲染器保留進度、失敗仍可操作，以及跨場景尋寶不能誤判。守護者須通過當次句型且每次試煉只領一次；儲存失敗允許重試。

## 瀏覽器驗收

透過 HTTP 開啟 localhost 的 ?dev=1。此模式不連接學生雲端成績。固定畫質後，在冒險選單執行「暖機＋巡檢空間數量兩輪」：依目前場景／學習大廳數量暖機一輪、量測兩輪；返回原場景後下載紀錄。

比較 round 1／2 同場景的 geometries、textures、drawCalls 與 failedTextures。p95Ms 來自巡檢累積／最近最多 1800 個可見幀，並不是每個場景獨立的穩態效能。繪圖資源數不等於完整 GPU 記憶體；背景幀不納入。

本次另以只存在審查資料夾的私用預覽注入 WebGL 失敗及模擬語音事件，完成第一關十二字、開門與前往市集，再恢復真正 3D；該注入程式不隨網站發布。模擬辨識成功不等於真實麥克風辨識品質。

小尺寸版面檢查以 DOM 實際尺寸為準。此次內嵌瀏覽器最低實際寬度為 480px，已確認大廳搜尋與題卡；不宣稱完成 390px 手機或多點觸控驗收。真實手機、麥克風、各支線完整通關及 30 分鐘硬體測試仍須在目標設備進行。

本次測試數與原始巡檢紀錄見 ../docs/RELEASE_2_6_0_HANDOVER.md 及 docs/validation/。

## v2.6 新增驗收

溫室測試涵蓋八步觀察與口說、防跳步、錯誤設定、完整片語、檢查點復原、支線門檻、模型實體／走道、過期回呼、完整單檔 GAS 實際保存、舊後台漏存保護。畫面層採實際 3D 瀏覽器檢查；口說端到端採本機模擬辨識，不等於真實麥克風辨識品質。
