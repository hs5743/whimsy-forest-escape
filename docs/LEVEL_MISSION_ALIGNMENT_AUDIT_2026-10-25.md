# 各關卡單字、任務與過關方式對照檢核

日期：2026-10-25 至 2026-10-26（Asia/Taipei）  
檢核基底：`main`，`15a12c5`（v2.8.0；本地 `main` 與 `origin/main` 相同）  
範圍：zone1–zone21 與 `learningHub`。本報告整理原始碼任務／場景定義與詞彙；本階段未修改遊戲程式、場景素材或部署。雲端實機操作與未驗證項目另見配套報告。

## 結論摘要

1. **zone1 是目前最完整的設計基準**：每一步都先找到實際場景物件，再口說指定單字，通過後才解鎖下一步；物件、單字、順序與過關狀態彼此連動。
2. **zone2–zone10 保留各自原有謎題，但目前通關主要檢查謎題狀態，沒有與每個謎題步驟一致的口說門檻**。若要回到 zone1 的學習形式，應在既有操作達標後增加口說確認；不需要新增 3D 物件或假裝玩家能搬動場景物件。
3. **zone11–zone21 已大多採「點選場景目標 → 面板選線索／完成狀態 → 口說」**，但部分任務文字寫成了實際繪圖、組裝、拾取或清理，程式實際只記錄「選擇／點到／口說」。近期可行修正是先讓任務文字如實描述已存在的互動；要做到物件移動或作品改變，另列為需要新增程式互動的工作。
4. **幾處明確的詞彙與步驟對不上**：zone2 的 `BANANA`、`SWEET` 不是本次訂單必需內容；`OPEN` 不參與結帳，但完成採買後是打開花園吊橋的必需轉場詞。zone8 的解題裝備是 `COAT / GLOVES / BOOTS`，但詞表沒有 `COAT`，`GLOVES / BOOTS` 也不在參考字表索引；zone11 的 `SPOON` 只是額外練習；zone12 的 `DRAW` 是選獅子圖卡，並沒有繪圖操作。
5. 依專案內 GEPT 索引，zone6 `SHIP`、zone7 `CLOUD`、zone9 `THINK`、zone10 `ISLAND` 超出索引。這是**本地索引比對結果**，不是對單字本身正誤的判斷；若保留，應標成延伸詞，不計入 GEPT 核心新詞。

## 判讀規則

- **符合**：目前場景物件、任務操作、口說詞和實際通關條件相互支持。
- **部分符合**：主題物件存在，但任務描述誇大了程式實際執行的動作，或有詞彙未參與謎題。
- **不吻合**：必要單字沒有對應的關卡線索／過關作用，或詞彙所指物與被點選的場景目標不同。
- **低成本**：只改任務文字、詞表標示或將詞彙標成複習／延伸。
- **中成本**：改既有關卡狀態流程，例如加口說確認、收集後隱藏既有模型；不新增場景資產。
- **高成本**：新增物件、點擊目標、動畫或真正的場景操作。報告不把這類項目當成近期必要修正。

### 場景依據與可操作性分級

- **zone1 已有雲端畫面實機核對**：房間可見磚牆、木地板、雕花木門、燭台圓桌、側邊書桌與地毯。從燭台轉向書桌時，紅色魔法書呈現在雕花門前、靠近桌面上方的位置，看起來像浮空物；桌面有綠色墊面但較空。第一步 `LIGHT` 對應畫面上真實可見的燭台，符合順序任務。任務提示應稱「書桌旁的燭台」，不可說成燭台就在桌面上；魔法書若本來設計為浮空，宜用一致的微光／浮空表現讓意圖清楚。點擊遠處魔法書時，畫面提示要靠近並對準物件，沒有改變步驟或玩家進度。
- **zone2–zone21 的表格是原始碼與場景建置定義核對，不是雲端 3D 畫面驗收**。因此這些關卡所列物件代表程式定義的目標，不等同於已證實它們在玩家鏡頭中清楚可見或容易點選。近期文字／口說調整只適用於該關目標能在實際遊玩視角中看見、辨認及操作的情況；若目標被遮住、太遠、外觀不符或不存在，先改用當前可見的既有目標，否則將該步標成待場景檢視，不列必過條件。
- **zone2 來源碼補充**：市集建置有可互動的蘋果、香蕉、麵包、牛奶實物目標，其點擊回呼會開各自的口說卡並加入背包；背包對重複 ID 只保留一份。市集解謎器則只檢查購物面板 `cart=[2,1,0]` 與 `paid=true`。兩者目前是分離狀態。城門吊橋使用 `OPEN` 口說卡觸發前往 zone3，因此 `OPEN` 是轉場必需詞，不能因它不在結帳求解條件內就從整關詞彙要求刪除。這些為程式路徑比對，市集 3D 物件的實際可見度仍待雲端解鎖後驗收。
- **zone3 來源碼補充**：場景建立噴泉、兔子、青鳥、古樹四個可互動目標；噴泉與三位夥伴的口說回呼都是空函式。照護謎題在任務面板獨立處理工具與目標配對，並沒有檢查場景點擊或口說結果。`LEAF / SEEDS` 雖是必要配對標籤，卻不在 zone3 詞表；近期可先視為解謎工具，不要宣稱是已教完的新詞。花園出口另用 `OPEN` 口說卡通往 zone4。以上為程式路徑比對，場景模型實際可見度仍待雲端解鎖驗收。

## 進度名稱應區分，避免把「解謎完成」當成「單字全學完」

目前至少有三種分開保存的狀態：

1. **本關任務解謎**：zone1–zone10 的 `RealmQuests` 或支線章節 `solved` 狀態；這是多數出口／前進傳送門檢查的依據。
2. **本關詞彙收集**：場景口說成功後寫入玩家的 `completedWords`。區域詞全收集會觸發關主試煉提示，但不等同於解開本關主謎題或主線出口。
3. **支線章節步驟**：zone11–zone21 由各章節保存的 stage/spoken 狀態決定，例如餐廳送餐、校園迎賓、圖書館八個閱讀步驟；這些完成條件不可被地圖詞彙數量代替。

**建議畫面用詞分開**：任務面板顯示「謎題進度／口說步驟」，區域收集顯示「本關單字 X/Y」，NPC 顯示「可挑戰關主試煉」。地圖前進按鈕只呈現真正阻擋該出口的條件，避免玩家以為單字全收集才可通關，或反過來以為口說單字就代表謎題已過。此為 UI／流程名稱對齊，中成本，不需新場景素材。

## 英語學習大廳

`learningHub` 與逃脫關卡不同，是自由選題與反覆口說，不需要增加謎題或解鎖門檻。入口由場景中的書本與地球儀目標進入；大廳提供主題單字、句型、複習、收藏與搜尋。**更正：目前雲端介面顯示 622 個詞彙範圍、15 個主題與 140 組可口說句型**；專案交接資料記錄其中 618 詞取自 GEPT Kids 參考字表，另有 4 個標示為創客補充詞。先前本段的 603 詞、88 組句型與八個主題是過期數字，已依目前雲端介面與專案交接資料修正。大廳支援聽示範、慢速播放、口說辨識、收藏、熟悉度、學習積分、紀錄保存與待同步資料。

## 關卡進度與大廳經驗值

這項檢查與任務文案不同，屬於跨區域進度流程：場景傳送門會透過 `RealmQuests.canTravel()` 檢查前一主線關卡是否完成；星圖的 `travelToZone()` 則檢查 `isZoneUnlocked()` 後，以 `directAccess: true` 傳送，略過傳送門的任務完成條件。主線關卡的 `isZoneUnlocked()` 主要依玩家等級判定。學習大廳首次學習的獎勵會加進同一個玩家 `profile.xp` 並重算等級。因此，只要先在大廳累積足夠 XP，玩家就可能從星圖跳進等級已開放、但主線前置任務尚未完成的關卡。

這是從目前程式路徑確認的進度風險，**尚未在低等級雲端訪客帳號實際重現**。建議保留大廳的自由選題與經驗獎勵，同時讓星圖與傳送門採同一套主線條件：可回訪已抵達的關卡，但不能只靠等級跳過未完成的主線關卡；支線依原有父關卡狀態開放。這是程式流程調整（中成本），不需要新增場景物件或改變任何關卡謎題。若希望玩家自由跳關，則需把星圖明確定位為自由探索，接受主線順序可能被略過的取捨。

### 流程與測試驗收

- 主線與支線的星圖、傳送門及返回路線共用關卡完成狀態；支線依其指定父關，主線依前一站與完整祖先路徑檢查。直接切換不再繞過必要前置關卡；地圖可顯示具體阻擋原因。
- zone2–zone10 的關卡 reducer 與場景口說卡共用已驗證詞彙紀錄；錯詞、缺少解題條件、重複回呼、取消卡片或舊場景延遲回呼不得完成步驟。
- GEPT 詞彙對照仍依專案整理的索引，不宣稱已逐頁重讀目前工作目錄不存在的原始 PDF。新增關卡核心詞有測試檢查來源與跨章重複；複習／延伸詞不冒充必要新詞。
- `npm run build:gas` 重建完整 Apps Script schema 與單檔版本；`npm test` **351/351 通過**，`git diff --check` 通過。
- 雲端發布 SHA、Pages 動作狀態、真實玩家流程和 Web Speech API 麥克風辨識需在實際部署後另記錄。測試使用的 `verifiedWord` 是程式測試證據，不可表述為真實口說辨識。
